# User stories and acceptance scenarios

These stories describe the behavior demonstrated by the prototype. The clinical roles are simulated. Requirement IDs refer to the [PRD](../PRD.md), and case IDs can be opened in the [live workspace](https://trial-review-desk-akshata.lovelybell1.chatgpt.site/).

| ID | User story | Acceptance scenario | Requirements |
|---|---|---|---|
| US1 | As a research coordinator, I want to see who owns each possible match and which visit is coming up so I can prioritize review. | Given the starting queue, when I filter by protocol, owner or status, then the visible queue and analytics use the same selection. Each case opens its protocol checks and dated sources. | R1, R7 |
| US2 | As a coordinator, I want to mark conflicting or missing evidence and assign a follow-up so I can keep uncertainty visible. | Given C002's conflicting excerpts, when I record the conflict and assign a follow-up, then the task requires a check, issue, owner and deadline. Resolving it requires a note. The assessment changes through a separate review action. | R2, R3 |
| US3 | As a coordinator, I want a temporary blocker to bring a case back to review when new evidence arrives so follow-up is easier to track. | Given C001 is waiting on a biomarker, when I load the fictional update from the Watchlist, then the original note remains available and the criterion needs a fresh assessment. Its task stays open until resolved. | R4, R10 |
| US4 | As a coordinator, I want to record a structured reason when a possible match closes so others can explain the outcome. | Given C005 has a confirmed exclusion, then handoff stays disabled even with the inclusions met. When closing a case as unsupported on current evidence after all other review work is resolved, I must record the ineligible disposition and reason. | R5, R6, R9, R15 |
| US5 | As a coordinator, I want to correct an AI suggestion and cite the right excerpt so another reviewer can see why it changed. | Given C007 L4 cites the earlier note, when I override it with the updated evidence and save as Coordinator B, then the original suggestion remains visible and the case shows the reviewer, time and error category. History preserves both states. | R4, R11 |
| US6 | As a product manager, I want to distinguish manual review activity from benchmark performance so I can see both the model's errors and the work people do to correct them. | Given one suggestion has been corrected twice, then it counts once as reviewed, once as overridden, and twice as an override action. The fixed benchmark stays the same. | R12 |
| US7 | As a clinical lead, I want a concise visit brief with sources so I can quickly understand the coordinator's proposed next step. | Given C007 has a documented review, when I preview the brief in the Inspector, then it shows the trial, reviewed evidence, open question, and next action. Activating the citation focuses the relevant excerpt in the case. | R5, R14 |
| US8 | As a trial operations lead, I want to see which protocol checks block otherwise-cleared cases so I can investigate enrollment bottlenecks. | Given a filtered, fully reviewed cohort, then the protocol card shows total blocked pairs and pairs with each check as the sole blocker. Unresolved pairs are excluded from the reviewed denominator. | R7, R13 |
